Backend Endpoints List (Organized respective to Roles):
1. Authentication & Onboarding (Shared)
These endpoints handle the initial gatekeeping and user creation.
[✅] POST /register
   * Action: Registers a standard User/Student.
   * Fields: full_name, email, password, birthday, contact_no, affiliation.
   * Associated Screen: Sign Up Flow (Steps 1-3).
   * ROUTE: POST /register → RegisteredUserController@store
[✅] POST /register/teacher
   * Action: Registers a Teacher/Affiliate and flags their account status as "Pending Verification".
   * Fields: Standard user fields + institutional_credentials (file upload).
   * Associated Screen: Teacher / Affiliate Sign-Up Flow.
   * ROUTE: POST /register → RegisteredUserController@store (role=teacher now supported)
   * DB: users.role has 'teacher' enum, users.institutional_credentials_url, users.status='pending_verification'
[✅] POST /login
   * Action: Authenticates user via Laravel Sanctum and redirects to their role-specific dashboard.
   * Fields: email, password.
   * Associated Screen: Log In Page.
   * ROUTE: POST /login → AuthenticatedSessionController@store
[✅] POST /forgot-password & POST /reset-password
   * Action: Triggers password recovery email and processes the new password.
   * Fields: email, password, password_confirmation.
   * Associated Screen: Forgot Password / Password Reset Flow.
   * ROUTE: POST /forgot-password → PasswordResetLinkController@store
   * ROUTE: POST /reset-password → NewPasswordController@store
[✅] POST /logout
   * Action: Destroys the Laravel Sanctum session and redirects the user to the Landing Page.
   * ROUTE: POST /logout → AuthenticatedSessionController@destroy
[✅] GET /email/verify/{id}/{hash}
   * Action: The destination route for the email verification link clicked by the user. Updates the email_verified_at column.
   * ROUTE: GET /verify-otp → VerifyOtpController@show (OTP-based approach)
   * ROUTE: POST /verify-otp → VerifyOtpController@verify
[✅] POST /email/verification-notification
   * Action: Resends the verification email if the user lost the initial one.
   * Associated Screen: Alert: Email Verification Required.
   * ROUTE: POST /resend-otp → VerifyOtpController@resend

Template 1: The Inertia Page Render (GET)
Use this for endpoints that load a screen (e.g., GET /marketplace, GET /admin/dashboard, GET /shells/{id}/map). Goal: Fetch data using Eloquent and pass it to the React frontend.
PHP
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Inertia\Inertia;
use App\Models\Certification;

class MarketplaceController extends Controller
{
   public function index()
   {
       // 1. Fetch data from the database (using Eager Loading to prevent N+1 issues)
       $shells = Certification::with('creator')->where('status', 'published')->get();

       // 2. Render the React component and pass the data as 'props'
       return Inertia::render('Student/Marketplace/Index', [
           'shells' => $shells,
           // Pass any other needed data, like current user's sand dollars
           'sand_dollars' => auth()->user()->sand_dollars, 
       ]);
   }
}

Template 2: The Form Submission / Action (POST/PUT)
Use this for user actions (e.g., POST /register, POST /modules/{id}/quiz/submit, POST /shop/buy). Goal: Validate input, perform database logic, and redirect back to the frontend with a success/error message. Never return raw JSON for Inertia web routes.
PHP
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use App\Models\Module;
use App\Models\UserModuleProgress;

class QuizController extends Controller
{
   public function submit(Request $request, $moduleId)
   {
       // 1. Always validate incoming request data first
       $validated = $request->validate([
           'answers' => 'required|array',
           'answers.*.question_id' => 'required|exists:questions,id',
           'answers.*.selected_option' => 'required|string',
       ]);

       // 2. Perform Business Logic (e.g., Grade the quiz)
       $module = Module::findOrFail($moduleId);
       $score = $this->calculateScore($module, $validated['answers']);

       // 3. Database Updates
       UserModuleProgress::updateOrCreate(
           ['user_id' => auth()->id(), 'module_id' => $moduleId],
           ['score' => $score, 'status' => $score >= 80 ? 'completed' : 'failed']
       );

       // 4. Redirect back to the React frontend with flash session data
       // Inertia will catch this and show a toast/alert without reloading the page!
       if ($score >= 80) {
           return redirect()->route('shells.map', $module->certification_id)
                            ->with('success', 'Sandbox Passed! +50 Sand Dollars');
       }

       return redirect()->back()->withErrors(['quiz' => 'Score too low, try again.']);
   }
}

Template 3: The File Upload (POST)
Use this for Content Creators uploading PPTs/Videos or users uploading verification IDs. Goal: Securely handle multipart/form-data, push to storage (like AWS S3), and save the URL to the database.
PHP
<?php

namespace App\Http\Controllers\Creator;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use App\Models\ModuleContent;

class ModuleContentController extends Controller
{
   public function store(Request $request, $moduleId)
   {
       // 1. Validate file size and type (CRITICAL for videos)
       $request->validate([
           'file' => 'required|file|mimes:mp4,pdf,pptx|max:500000', // 500MB max
           'content_type' => 'required|string'
       ]);

       // 2. Store the file on the specified disk (e.g., 's3' or 'public')
       $path = $request->file('file')->store('module-contents', 's3');

       // 3. Save the resulting file path/URL to the database
       ModuleContent::create([
           'module_id' => $moduleId,
           'content_type' => $request->content_type,
           'file_url' => $path,
       ]);

       // 4. Redirect back to the creator's sandbox editor
       return redirect()->back()->with('success', 'Media uploaded successfully!');
   }
}
	Template 4: The Stateless Webhook Listener (API POST)
Use this ONLY for Xendit webhooks. Goal: Receive a background POST request from an external server, verify security, process data, and return a standard 200 OK JSON response. (Do not use Inertia here, as there is no user browser to redirect).
PHP
<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use App\Models\EnrollmentRequest;
use Illuminate\Support\Facades\Log;

class XenditWebhookController extends Controller
{
   public function handle(Request $request)
   {
       // 1. Verify the Xendit Callback Token (Security)
       if ($request->header('x-callback-token') !== env('XENDIT_WEBHOOK_TOKEN')) {
           return response()->json(['error' => 'Unauthorized'], 401);
       }

       // 2. Find the pending enrollment
       $enrollment = EnrollmentRequest::where('external_id', $request->external_id)->first();

       if (!$enrollment) {
           return response()->json(['error' => 'Enrollment not found'], 404);
       }

       // 3. Idempotency Check (Did we already process this?)
       if ($enrollment->status === 'PAID') {
           return response()->json(['status' => 'Already processed'], 200);
       }

       // 4. Process Payment & Generate Voucher
       if ($request->status === 'PAID') {
           $enrollment->update(['status' => 'PAID']);
           
           // Generate voucher logic here...
           // $this->generateVoucher($enrollment);
       }

       // 5. MUST return a 200 OK so Xendit knows you received it and stops retrying
       return response()->json(['status' => 'success'], 200);
   }
}
	A Note for the Backend Devs:
utilize Laravel FormRequests for validation instead of writing validation rules directly in the controllers. It keeps the controllers clean and makes the React error-handling seamless. When a validation fails in Laravel, Inertia automatically passes those errors to React as an errors prop, allowing you to easily display red text under your form inputs in Figma/React!
